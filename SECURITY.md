# Security Policy

## Supported versions

There is no public release yet. Security fixes are made only on the active development branch.

## Reporting a vulnerability

Do not publish exploits involving packet validation, server crashes, arbitrary file access, or multiplayer authority bypasses in a public issue. While the repository is private, collaborators should use a private GitHub Security Advisory when available and contact the repository owner through an already established private channel. Before any public release, the owner must enable and test private vulnerability reporting or publish a working private security contact. This is a release blocker.

Provide:

- affected commit and environment;
- reproduction steps or a minimal packet trace;
- expected impact;
- whether the issue works against a Dedicated Server.

Do not send credentials, personal data, proprietary Calamity files, or unrelated server logs.
